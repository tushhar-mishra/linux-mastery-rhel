## What it is

In a company with 500 servers, nobody creates `alice` on each machine by hand. Users and groups live in **one central directory**, and every server asks it.

Words you'll meet:

- **Directory service**: a central database of users, groups, passwords and rules.
  - **LDAP** (Lightweight Directory Access Protocol) is the standard way to query one.
  - **Active Directory (AD)** is Microsoft's directory.
  - **Red Hat IdM** (Identity Management, built from the open-source **FreeIPA** project) is Red Hat's.
  - **OpenLDAP** is a plain open-source LDAP server.
- **Kerberos**: a login system based on **tickets**. You prove your password once to a central server (the KDC, Key Distribution Center) and get a time-limited ticket. Services trust the ticket, so your password isn't sent to each one. AD and IdM both use Kerberos.
- **NSS** (Name Service Switch): the glibc feature that answers "**who** is UID 1001? which groups is alice in? where's her home?" (identity lookups). Configured in `/etc/nsswitch.conf`.
- **PAM** (topic 029): answers "**is this really alice, and may she log in now?**" (authentication and access).
- **SSSD** (System Security Services Daemon): the service on each Linux machine that talks to the directory and feeds both NSS and PAM, with a local cache.

## Why it exists

- **One place to manage people:** add, disable or remove a user once, and every server follows.
- **Consistent UIDs everywhere:** essential for NFS shares (topic 079), where file ownership is just a number.
- **Single sign-on:** with Kerberos, users log in once and reach many services.
- **Central rules:** "the dba group may log in only to database servers", and even central sudo rules.

## Analogy

Local accounts are **each shop keeping its own staff list**. A directory is **head office's HR system**. Each shop (server) has a **receptionist (SSSD)** who phones head office to check names and IDs, and keeps a **notebook copy (the cache)** so work continues if the phone line is briefly down. Kerberos is a **day pass**: show your ID at the main gate once, then wave the pass at each door.

## How it works inside

### Two different questions

| Question | Answered by | Configured in |
|---|---|---|
| "Who is UID 1001? What groups is alice in? What's her home?" | **NSS** in glibc | `/etc/nsswitch.conf` |
| "Is this really alice? May she log in now?" | **PAM** | `/etc/pam.d/*` (generated by authselect) |

### NSS: looking things up in order

```
passwd:     files sss systemd
group:      files [SUCCESS=merge] sss systemd
hosts:      files dns myhostname
automount:  files sss
```
Each line lists **sources in order**:
- `files` = `/etc/passwd`, `/etc/group`, `/etc/hosts`
- `sss` = ask SSSD
- `systemd` = temporary users that systemd creates for services (`DynamicUser=`)
- `dns` = DNS name lookup (topic 063)
- `myhostname` = always resolve the machine's own name

When any program needs user info, glibc walks this list. That's why `ls -l` can show names of users who aren't in `/etc/passwd` at all.

RHEL 10's default (authselect profile `local`) has no `sss`. Selecting the `sssd` profile adds it.

### SSSD inside

```
 login / ls / id ─► glibc NSS ─► nss_sss ─┐
 sshd / su / sudo ─► PAM ─► pam_sss ─────┤─► sssd ─► providers (id, auth, access) ─► IdM / AD / LDAP
                                          │            (LDAP queries + Kerberos)
                                          └─► local cache /var/lib/sss/db/
```
- **Cache:** looked-up users and groups (and optionally credentials) are stored locally, so lookups are fast and logins keep working for a while if the directory is unreachable.
- **Kerberos needs correct time and DNS.** Tickets are rejected if the clocks differ by more than about 5 minutes (time sync is topic 069). Servers are found through DNS service records (topic 063).
- **Access control:** `access_provider` decides who may log in **where**: IdM's HBAC (Host-Based Access Control) rules, AD group policies, or a simple allow-list of groups.
- SSSD can also serve **sudo rules**, **SSH public keys** and **automount maps** from the directory.

### Ubuntu

Same SSSD and the same `realm join`. PAM is updated with `pam-auth-update` instead of authselect, and `/etc/nsswitch.conf` is edited (or managed) directly.

## Commands

```bash
grep -vE '^#|^$' /etc/nsswitch.conf | head -4
```
```
passwd:     files systemd
group:      files [SUCCESS=merge] systemd
netgroup:   files
automount:  files
```
- A machine with local accounts only.

```bash
getent passwd alice
getent -s files passwd alice      # ask ONLY local files
getent group admins ; id alice
```
- `getent` asks NSS exactly the way programs do. **Use it instead of `grep /etc/passwd`**: directory users aren't in that file.

### Joining a domain

```bash
# Red Hat IdM / FreeIPA
sudo dnf install -y ipa-client
sudo ipa-client-install --domain=example.com --realm=EXAMPLE.COM --mkhomedir
```
- Enrols the host and configures SSSD, authselect, Kerberos and time sync in one go.

```bash
# Active Directory
sudo dnf install -y realmd sssd adcli oddjob oddjob-mkhomedir samba-common-tools
realm discover example.com
sudo realm join example.com -U Administrator
sudo realm permit -g linux-admins@example.com
```
- `realm discover` shows what kind of domain it is and what's needed. `realm join` creates the computer account and writes `/etc/sssd/sssd.conf`. `realm permit -g` allows only that group to log in.

```bash
authselect current
```
```
Profile ID: sssd
Enabled features:
- with-mkhomedir
```

### Operating and troubleshooting

```bash
systemctl status sssd
sudo sssctl domain-status example.com
```
```
Online status: Online

Active servers:
AD Global Catalog: dc1.example.com
AD Domain Controller: dc1.example.com
```

```bash
sudo sssctl user-checks alice
```
- Runs the NSS lookup and the PAM checks for one user and explains what fails.

```bash
sudo sss_cache -E                   # throw away cached entries (after changes in the directory)
id alice@example.com                # AD users may need the domain suffix (use_fully_qualified_names)
klist ; kinit alice                 # show / get Kerberos tickets
journalctl -u sssd --since -15min
```

## Where you'll use it

- **Corporate Linux fleets:** almost always joined to AD or IdM. "User can't log in" tickets mean checking SSSD.
- **NFS home directories** (topic 079): need the same UIDs everywhere, which a directory provides.
- **Kubernetes:** OIDC/LDAP integration for cluster users is the same idea (a central identity provider) at a different layer.
- **Security:** disabling a leaver in AD removes their access to every joined server immediately.

## When it breaks

| Symptom | Likely cause | Check / fix |
|---|---|---|
| `id: 'alice': no such user` but she exists in the directory | SSSD down or offline, a wrong filter, or a fully-qualified name is required | `sssctl domain-status`; `getent passwd alice@domain` |
| A change in the directory isn't visible | Cache | `sss_cache -E` |
| "Permission denied" with the correct password | Access rules (HBAC, `realm permit`) | `sssctl user-checks alice`; `journalctl -u sssd` |
| Kerberos error "Clock skew too great" | The clocks differ | Fix time sync (`chronyc tracking`, topic 069) |
| No home directory at first login | `with-mkhomedir` off, or `oddjobd` not running, or homes are automounted | `authselect current`; autofs maps (topic 079) |
| Files on NFS show numbers instead of names | UID mismatch, or NFSv4 ID-mapping domain mismatch | Consistent UIDs; `Domain=` in `/etc/idmapd.conf` |

## Quick recap

- **NSS** answers "who is this?" (`/etc/nsswitch.conf`, `getent`). **PAM** answers "may they log in?".
- **SSSD** connects both to a central directory (IdM/FreeIPA, AD, LDAP), with a cache for speed and offline logins.
- Kerberos = ticket-based login. It needs correct **time** and **DNS**.
- Join with `ipa-client-install` or `realm join`; debug with `sssctl`, `sss_cache -E`, `journalctl -u sssd`.

**Interview questions**

1. *NSS vs PAM?* NSS maps names to IDs and returns account information (who). PAM authenticates and enforces access and session rules (may they log in).
2. *Why does `grep alice /etc/passwd` find nothing for a domain user?* Domain users come from SSSD through NSS, not the local file. Use `getent passwd alice`.
3. *Why is time synchronisation critical for domain logins?* Kerberos tickets carry timestamps, and servers reject them if clocks differ by more than a few minutes.
