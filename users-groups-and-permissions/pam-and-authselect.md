# PAM & authselect: Authentication Policy on RHEL 10

> **Sessions:** S93 · **[Advanced/Optional]** (supports password policy and privileged-access topics) · **[Production Practice]**
> **Related:** [Passwords & aging (pwquality)](passwords-and-aging.md) · [sudo](sudo-and-privileged-access.md) · [SSH hardening](../networking-and-ssh/ssh-server-hardening.md) · [System logging (`/var/log/secure`)](../logs-scheduling-and-packages/system-logging.md) · [Central identity (NSS/SSSD)](central-identity-nss-sssd.md) · [auditd](../firewall-and-selinux/auditd.md)

## 1. Overview

**PAM (Pluggable Authentication Modules)** lets programs (login, sshd, su, sudo, passwd, cockpit…) delegate authentication and session policy to configurable, stackable **modules**. On RHEL, the shared stacks (`system-auth`, `password-auth`, …) are generated by **authselect**. Don't edit them by hand.

> ⚠️ **Safety rules:** keep a **root session open** while changing PAM, back up `/etc/pam.d`, test with a **new** login, prefer a VM snapshot, and use test users.

## 2. Configuration Structure

| Path | Content |
|---|---|
| `/etc/pam.d/<service>` | Stack for one program (`sshd`, `login`, `su`, `sudo`, `passwd`, `cockpit` …) |
| `/etc/pam.d/system-auth`, `password-auth`, `fingerprint-auth`, `smartcard-auth`, `postlogin` | Shared stacks, **symlinks to `/etc/authselect/`** (managed) |
| `/etc/security/*.conf` | Module settings: `pwquality.conf`, `faillock.conf`, `limits.conf`, `time.conf`, `access.conf`, `pwhistory.conf` (+ `.d/` drop-ins) |

**Rule format:** `<type> <control> <module> [arguments]`

```
auth       required     pam_faillock.so preauth
auth       sufficient   pam_unix.so try_first_pass
account    required     pam_unix.so
password   requisite    pam_pwquality.so local_users_only
session    optional     pam_umask.so
auth       include      system-auth
````

| Type | Purpose |
|---|---|
| `auth` | Prove identity (password, key, token) |
| `account` | Is this account allowed now? (expired, locked, time, host) |
| `password` | Changing credentials (quality, history) |
| `session` | Setup/teardown (limits, environment, home dir, logging) |

| Control | Behavior |
|---|---|
| `required` | Must succeed; failure is reported after the rest of the stack runs |
| `requisite` | Must succeed; failure returns immediately |
| `sufficient` | Success ends this type's stack (if nothing required failed before); failure is ignored |
| `optional` | Result matters only if it's the only module of this type |
| `include` / `substack` | Pull in another file's stack |
| `[success=1 default=ignore]` | Advanced bracket syntax for fine control |

**SSH note:** with **key-based** logins, sshd skips the PAM **auth** stack; **account** and **session** still run (`UsePAM yes`). Put access restrictions in `account` if they must apply to key logins too.

## 3. authselect

````bash
authselect current                         # profile + enabled features
authselect list                            # available profiles (RHEL 10: local, sssd, winbind …)
authselect list-features local             # features of a profile
authselect enable-feature with-faillock    # ADD a feature to the current profile
authselect disable-feature with-faillock
authselect select sssd with-mkhomedir --force   # REPLACES profile + feature set ⚠️
authselect apply-changes                   # regenerate after editing a custom profile
authselect create-profile myprof -b local  # custom profile in /etc/authselect/custom/ [Advanced]
authselect backup-list ; authselect backup-restore <name>
````

Common features: `with-faillock`, `with-mkhomedir`, `with-pwhistory`, `without-nullok`, `with-sudo`, `with-fingerprint`, `with-smartcard`.

## 4. Common Modules

| Module | Purpose | Config |
|---|---|---|
| `pam_unix` | Local `/etc/passwd`/`shadow` auth | — |
| `pam_sss` | SSSD (IdM/AD/LDAP) | sssd.conf |
| `pam_pwquality` | Password strength | `/etc/security/pwquality.conf` |
| `pam_pwhistory` | Prevent password reuse | `/etc/security/pwhistory.conf` |
| `pam_faillock` | Lock after failed attempts | `/etc/security/faillock.conf` |
| `pam_limits` | Resource limits per user/group | `/etc/security/limits.conf`, `limits.d/` |
| `pam_time` | Time-based access | `/etc/security/time.conf` |
| `pam_access` | Host/user/origin access rules | `/etc/security/access.conf` |
| `pam_listfile` | Allow/deny by list file | Arguments |
| `pam_wheel` | Restrict `su` to wheel | `/etc/pam.d/su` |
| `pam_nologin` | Block non-root logins while `/etc/nologin` exists | — |
| `pam_env`, `pam_umask`, `pam_mkhomedir` | Environment, umask, create home on first login | — |

## 5. Practicals

### 5.1 Inspect

````bash
ls -l /etc/pam.d ; cat /etc/pam.d/sshd ; cat /etc/pam.d/system-auth
mkdir -p /root/pam-backups ; cp -a /etc/pam.d /root/pam-backups/pam.d.$(date +%F_%T)
````

### 5.2 Allow only listed users to log in via SSH (`pam_listfile`)

````bash
cp /etc/pam.d/sshd /etc/pam.d/sshd.bak
echo testalice > /etc/ssh/allowedusers ; chmod 600 /etc/ssh/allowedusers
# add near the top of the ACCOUNT section of /etc/pam.d/sshd (also covers key logins):
#   account required pam_listfile.so item=user sense=allow file=/etc/ssh/allowedusers onerr=fail
ssh testalice@localhost   # allowed
ssh testbob@localhost     # denied (see /var/log/secure)
mv /etc/pam.d/sshd.bak /etc/pam.d/sshd       # rollback
````

No sshd restart is needed (PAM files are read for each login). For SSH specifically, `AllowUsers`/`AllowGroups` in sshd_config is usually simpler.

### 5.3 Password quality (`pam_pwquality`)

````bash
cat > /etc/security/pwquality.conf.d/90-local.conf <<'EOF'
minlen = 12
dcredit = -1
ucredit = -1
lcredit = -1
ocredit = -1
enforce_for_root
EOF
su - testbob -c passwd        # "short" → BAD PASSWORD; "Abcdef1!xyz9" → accepted
````

- **Negative credit** = at least that many characters of the class (`dcredit=-1` → ≥1 digit).
- **Positive credit** = each such character counts extra toward `minlen` (up to N).
- Other options: `minclass`, `maxrepeat`, `dictcheck`, `usercheck`.
- Root only gets a warning unless `enforce_for_root` is set.

### 5.4 Account lockout (`pam_faillock`)

````bash
authselect current                       # is with-faillock enabled?
authselect enable-feature with-faillock  # adds pam_faillock to system-auth/password-auth
grep faillock /etc/pam.d/system-auth
cat >> /etc/security/faillock.conf <<'EOF'
deny = 3
unlock_time = 600
fail_interval = 900
EOF
su - testbob ; su - testalice           # wrong password 3×
faillock --user testalice               # failure records
faillock --user testalice --reset       # unlock
````

root isn't locked unless `even_deny_root` is set.

### 5.5 Time-based access (`pam_time`)

````bash
# /etc/pam.d/sshd, account section:  account required pam_time.so
# /etc/security/time.conf  (services;ttys;users;times)
sshd;*;testalice;Wk0900-1700             # testalice via sshd only Mon–Fri 09:00–17:00
````

### 5.6 Resource limits (`pam_limits`)

````bash
cat > /etc/security/limits.d/90-testalice.conf <<'EOF'
testalice  hard  nofile  1024
testalice  hard  nproc   200
EOF
ssh testalice@localhost 'ulimit -n; ulimit -u'      # 1024 / 200
````

systemd services ignore `limits.conf`; set `LimitNOFILE=` / `LimitNPROC=` in the unit instead.

### 5.7 Restrict `su` to wheel

````bash
# /etc/pam.d/su — uncomment:
auth  required  pam_wheel.so use_uid
````

## 6. Production Practices **[Production Practice]**

- Change shared stacks only through authselect (features or a custom profile).
- Keep a console/out-of-band path; test in staging; roll out with configuration management.
- Prefer drop-in files (`*.conf.d/`, `limits.d/`).
- Monitor `/var/log/secure` and `faillock` for brute-force patterns.

## 7. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Nobody can log in after a PAM edit | Syntax/logic error | Use the open root session to restore the backup; otherwise `rd.break` |
| Manual changes to system-auth vanished | authselect regenerated the files | Use authselect features or a custom profile |
| Faillock never locks | Feature not enabled | `authselect enable-feature with-faillock` |
| Restriction bypassed with SSH keys | Rule in the `auth` stack | Move it to `account` |
| `authselect: … files were modified outside` | Hand edits detected | `authselect select … --force` (review first) or restore |
| Limits not applied to a service | systemd doesn't use pam_limits | `Limit*=` in the unit |

## 8. Interview Questions

| Question | Answer |
|---|---|
| What are the four PAM module types? | auth, account, password, session. |
| `required` vs `requisite`? | Both must pass; requisite stops immediately on failure, required continues the stack before failing. |
| Why not edit `/etc/pam.d/system-auth` directly? | It's generated by authselect and will be overwritten. |
| How do you enable account lockout on RHEL? | `authselect enable-feature with-faillock` + `/etc/security/faillock.conf`. |
| Does PAM auth run for SSH key logins? | No; auth is skipped, but account and session still run. |
