# Central Identity: NSS, SSSD & Directory Users (Concepts)

> **Track:** **[Production Practice]** · supports *Configure autofs* / home-directory tasks that use directory (LDAP/IdM) users **[RHCSA Core context]** · **Verified:** NSS and authselect defaults on a RHEL 10.2 UBI container (authselect 1.5.2, Oct 2026). ## 1. Two Separate Questions

Every login and every `ls -l` asks two different things:

| Question | Answered by | Configured in |
|---|---|---|
| **"Who is UID 1001? What groups is alice in? Where's her home?"** (identity lookup) | **NSS** (Name Service Switch) in glibc | `/etc/nsswitch.conf` |
| **"Is this really alice? May she log in now?"** (authentication & access) | **PAM** | `/etc/pam.d/*` (generated by authselect) |

Locally both are answered from files (`/etc/passwd`, `/etc/shadow`). In organizations both are answered by a **directory** (Red Hat IdM/FreeIPA, Active Directory, OpenLDAP) through **SSSD**.

## 2. NSS: How Names Are Resolved

```bash
grep -vE '^#|^$' /etc/nsswitch.conf        # RHEL 10 default (authselect profile "local"), verified:
#   passwd:     files systemd
#   group:      files [SUCCESS=merge] systemd
#   hosts:      files  dns myhostname
#   automount:  files
```

Each database lists **sources in order**: `files` (`/etc/passwd`…), `systemd` (dynamic users, e.g. `DynamicUser=` services), `sss` (SSSD), `dns`, `myhostname`. With the `sssd` authselect profile, `passwd:`/`group:` become `files sss systemd` and `automount:` can include `sss` (autofs maps from the directory).

```bash
getent passwd alice                 # ask NSS (all sources) exactly as programs do
getent -s files passwd alice        # only the files source
getent group sysadmin ; id alice    # groups as the system sees them
```

**This is why RHCSA notes insist on `getent` over `grep /etc/passwd`:** directory users don't exist in `/etc/passwd`, but they own files, log in, and get automounted homes.

## 3. SSSD Architecture

```
 login / ls / id ─► glibc NSS ─► nss_sss ─┐
 sshd / su / sudo ─► PAM ─► pam_sss ─────┤─► sssd (responders: nss, pam, sudo, autofs, ssh)
                                          │      └─ domain providers (id, auth, access) ─► IdM / AD / LDAP (LDAP + Kerberos)
                                          └─► local cache /var/lib/sss/db/ (offline logins, fewer lookups)
```

- **Caching:** SSSD caches identities and (optionally) credentials, so logins keep working briefly if the directory is unreachable, and lookups are fast.
- **Kerberos:** IdM/AD authentication uses Kerberos tickets, so **time synchronization** (chrony) and DNS (SRV records) must be correct.
- **Access control:** `access_provider` (e.g., IdM HBAC rules, AD GPOs, `simple_allow_groups`) decides who may log in where.
- **sudo, SSH keys, automount maps** can also come from the directory via SSSD responders.

## 4. Joining a Domain (Typical Commands)

```bash
# Red Hat IdM (FreeIPA)
dnf install -y ipa-client
ipa-client-install --domain=example.com --realm=EXAMPLE.COM --mkhomedir   # enrolls, configures sssd, authselect, Kerberos, chrony

# Active Directory (direct integration)
dnf install -y realmd sssd adcli oddjob oddjob-mkhomedir samba-common-tools
realm discover example.com
realm join example.com -U Administrator
realm permit -g linux-admins@example.com

# What got configured
authselect current                 # Profile ID: sssd   Enabled features: with-mkhomedir …
cat /etc/sssd/sssd.conf            # mode 0600, owned by root
```

## 5. Operating & Troubleshooting

```bash
systemctl status sssd ; journalctl -u sssd
sssctl domain-list ; sssctl domain-status example.com      # online/offline, active server
sssctl user-checks alice                                   # NSS + PAM checks for one user
sss_cache -E                                               # invalidate cached entries (after directory changes)
id alice@example.com ; getent passwd alice@example.com     # AD users may need the domain suffix (use_fully_qualified_names)
klist ; kinit alice                                        # Kerberos tickets
```

| Symptom | Likely cause | Check / fix |
|---|---|---|
| `id: 'alice': no such user` but she exists in the directory | SSSD down/offline, wrong filter, FQDN required | `sssctl domain-status`; `getent passwd alice@domain` |
| Directory change not visible | Cache | `sss_cache -E`; check cache timeouts |
| Login fails: "Permission denied" with correct password | Access rules (HBAC, `realm permit`) | `sssctl user-checks`; `journalctl -u sssd` |
| Kerberos errors, "Clock skew too great" | Time drift | `chronyc tracking`; fix NTP |
| Home directory missing at first login | `with-mkhomedir` not enabled / oddjobd not running, or homes are automounted | `authselect current`; autofs maps |
| Files show numeric owners on NFS | UID mismatch or idmap domain | Consistent UIDs from the directory; `/etc/idmapd.conf` `Domain=` for NFSv4 |

## 6. Interview Questions

| Question | Answer |
|---|---|
| NSS vs PAM? | NSS maps names ↔ IDs and provides account information; PAM authenticates and enforces access/session rules. |
| What is SSSD? | A daemon providing NSS/PAM (and sudo, autofs, SSH key) data from directories like IdM/AD/LDAP, with caching and offline support. |
| Why does `grep alice /etc/passwd` fail for domain users? | They're served by SSSD through NSS; use `getent passwd alice`. |
| Why is time sync critical for domain logins? | Kerberos rejects tickets when clocks differ beyond a few minutes. |
| How do NFS homes for directory users work? | autofs (maps from files or SSSD) + consistent UIDs from the directory + NFS server exports. |
